# 数据模型（11 张表）

> 数据库：`D:\vibe-mv\mv.db`（SQLite，`node:sqlite` 内置驱动）
> 本文件是**唯一 DDL 权威**。改表先改这里，再改 `scripts/db.mjs`，两边不许不一样。

## 0. 三条全局约定

| 约定 | 规则 | 为什么 |
|---|---|---|
| 时间 | 全部 `datetime('now','localtime')`，格式 `YYYY-MM-DD HH:MM:SS` | 老板看的是本地时间，不做时区换算 |
| 路径 | 一律**相对** `D:\vibe-mv-文件库\<slug>\` | 整个文件库可以整体搬盘，库不用改 |
| 主键 | 自增 `id` 只给数据库内部用；对外（网页 URL、命令参数、老板嘴里）一律用业务键 | 老板说的是 `turtle`，不是 `asset_id=7` |

**状态枚举（四档，不许扩张）**：`todo` → `partial` → `draft` → `done`。
`partial` = 有产出但不完整；`draft` = 完整待老板点头；`done` = 已过闸。

## 1. `songs` 歌

```sql
CREATE TABLE songs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  slug       TEXT NOT NULL UNIQUE,        -- jiaowo-laowangba，入库后永不改
  title      TEXT NOT NULL,               -- 叫我老王八
  dur        REAL,                        -- 片段时长（秒）
  bpm        REAL,
  music_key  TEXT,                        -- 调性，如 C major
  engine     TEXT,                        -- vibe-mv-flatpaper | vibe-knowledge-mv-yashu
  canvas     TEXT,                        -- 1920x1080@30
  note       TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

`slug` 是全部外键的锚点：老板说"存进去"时只报歌名，我负责映射到 slug。

## 2. `stages` 关卡

```sql
CREATE TABLE stages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  song_id     INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  gate        TEXT NOT NULL,              -- G0 G1 G2 G3 G3.5 G4 G5
  status      TEXT NOT NULL DEFAULT 'todo',
  started_at  TEXT,
  finished_at TEXT,
  note        TEXT,
  UNIQUE(song_id, gate)
);
```

建歌时**一次性插满 7 行**（G0…G5），不留空洞。首页的进度条直接 `group by status`，不用补空值。

## 3. `artifacts` 产物

```sql
CREATE TABLE artifacts (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  song_id INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  gate    TEXT NOT NULL,
  kind    TEXT NOT NULL,                  -- audio|music|lyrics|relay|storyboard|story|video|export|doc
  path    TEXT NOT NULL,                  -- 相对文件库的歌目录
  bytes   INTEGER,
  md5     TEXT,
  mtime   TEXT,
  note    TEXT,
  UNIQUE(song_id, path)
);
```

一个文件一行。**同一路径重复提交 = 更新这一行**（覆盖 bytes/md5/mtime），不新增。

> `artifacts` **只收二进制**（mp3 / png / mp4）。文本类产物（歌词轴、音乐档案、分镜稿）走下一张 `docs` 表，**全文入库**——因为网页要渲染它们的内容，不能只给路径。

## 3.5 `docs` 文本产物

```sql
CREATE TABLE docs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  song_id    INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  kind       TEXT NOT NULL,               -- lyrics|music|source-lyrics|relay|storyboard|brief|story
  path       TEXT,                        -- 相对文件库的歌目录；可为空（只入库不落文件）
  doc        TEXT NOT NULL,               -- 正文全文，JSON 或 Markdown 原文
  md5        TEXT,
  version    INTEGER NOT NULL DEFAULT 1,  -- 同 kind 可多版，默认取 max
  meta_json  TEXT,                        -- 从正文提炼的常用指标，省得每次 json_extract
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(song_id, kind, version)
);
```

**为什么文本进库、二进制不进库**：逐字轴 5KB、音乐 slim 档案 6KB，比一张图小几百倍，塞进 TEXT 字段毫无压力；而且页面要渲染「哪个字什么时候亮」，拿路径再请求一次只是多一个会坏的环节。60KB 的完整音乐档案（50–100ms 粒度，只有 `query.py` 用）则**只记路径**，留在 `artifacts`。

| `kind` | 内容 | 谁产 | 页面怎么用 |
|---|---|---|---|
| `lyrics` | 逐字轴 JSON（`lyrics[]` 每句含 `words[]`） | lyric-tapper | 单歌页渲染逐字时间轴；`json_each` 现查句数/字数 |
| `music` | 音乐 slim 档案（BPM/调性/响度/拍点） | song-analyzer | 单歌页头部指标 |
| `source-lyrics` | 老板给的原始歌词 | 老板 | 对照用 |
| `relay` / `storyboard` / `brief` | G3 创作稿与口述稿 | 分镜师 / 老板 | 单歌页正文渲染 |
| `story` | 装配后的 `story.json` | 引擎 | 一般不留，渲染前现导 |

**版本规则**：同一 `kind` 重新提交且 `version` 未指定时，覆盖 `max(version)` 那一行（不新建版本）；只有显式给 `version` 才新增一行。

## 4. `assets` 资产

```sql
CREATE TABLE assets (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  song_id   INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  asset_key TEXT NOT NULL,                -- turtle
  name      TEXT NOT NULL,                -- 老乌龟
  cat       TEXT NOT NULL,                -- 角色|道具|特效|背景
  angle     TEXT,                         -- 正面（见腹甲）|背视|侧视
  channel   TEXT,                         -- ai|svg
  status    TEXT NOT NULL DEFAULT 'todo',
  spec_json TEXT,                         -- 造型、配色、拆件档等自由结构
  note      TEXT,
  UNIQUE(song_id, asset_key)
);
```

`channel` 回答"这件要不要 AI 出图"：`ai` 进生图流程，`svg` 直接手绘。**一件只能选一边**。

## 5. `images` 图

```sql
CREATE TABLE images (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  asset_id   INTEGER NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
  path       TEXT NOT NULL,
  kind       TEXT NOT NULL DEFAULT 'ref', -- ref|picked|final|reject
  w          INTEGER,
  h          INTEGER,
  bytes      INTEGER,
  sha256     TEXT NOT NULL UNIQUE,        -- 内容指纹，天然去重
  prompt     TEXT,
  seed       INTEGER,
  workflow   TEXT,                        -- rh1|rh2|rh3|wf1..wf5|manual
  cost       REAL NOT NULL DEFAULT 0,
  picked     INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

**这张表是整个库最值钱的地方**：一张图为什么长这样，`prompt + seed + workflow` 三件套直接查得出来，不用翻日志。
`sha256 UNIQUE` 是幂等的根据——同一张图第二次提交会被忽略，不报错。

## 6. `svgs` SVG 代码

```sql
CREATE TABLE svgs (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  asset_id INTEGER NOT NULL REFERENCES assets(id) ON DELETE CASCADE,
  path     TEXT NOT NULL,
  symbol   TEXT NOT NULL,                 -- 与 asset_key 同名的 <symbol id>
  source   TEXT NOT NULL,                 -- 完整 SVG 文本
  version  INTEGER NOT NULL DEFAULT 1,
  approved INTEGER NOT NULL DEFAULT 0,
  bytes    INTEGER,
  note     TEXT,
  UNIQUE(asset_id, version)
);
```

**代码存库，文件也落一份**——引擎要 `<use>` 一个真实文件。两者必须由**同一次 save** 同时写，不许单独改磁盘上的 `.svg`（改了库里不知道 = 三处两样）。

## 8. `skill_runs` 技能调用流水

```sql
CREATE TABLE skill_runs (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  song_id     INTEGER REFERENCES songs(id) ON DELETE CASCADE,
  skill_id    INTEGER NOT NULL REFERENCES skills(id),
  gate        TEXT,
  run_key     TEXT NOT NULL UNIQUE,       -- sha1(slug|skill|gate|started_at)
  started_at  TEXT,
  ended_at    TEXT,
  ok          INTEGER NOT NULL DEFAULT 1,
  note        TEXT,
  artifact_id INTEGER REFERENCES artifacts(id) ON DELETE SET NULL
);
```

**只增不改**。`run_key` 用哈希而不是自增，是为了同一批数据重传两次不产生重复流水。

技能页的矩阵就是：

```sql
SELECT s.name AS skill, so.title AS song, count(*) AS n
FROM skill_runs r JOIN skills s ON s.id=r.skill_id JOIN songs so ON so.id=r.song_id
GROUP BY s.name, so.title ORDER BY n DESC;
```

## 9. `decisions` 老板的决定

```sql
CREATE TABLE decisions (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  song_id INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  scope   TEXT NOT NULL,                  -- song|gate|asset|image
  target  TEXT NOT NULL,                  -- 业务键：G3.5 / turtle / turtle-03
  verdict TEXT NOT NULL,                  -- picked|approved|rejected|angle-locked|gate-passed
  note    TEXT,
  at      TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

**只增不改**，纠错靠追加一条相反的（`rejected` 跟在 `picked` 后面，查最新一条说话）。这是唯一一份"人产生的数据"，删库重建时不可恢复——所以它必须随每次 save 写入。

CREATE TABLE costs (

## 12. 视图（页面直接查，不再写重复 SQL）

```sql
CREATE VIEW v_song_progress AS
SELECT so.id AS song_id, so.slug, so.title,
       count(*) FILTER (WHERE st.status = 'done')    AS done_gates,
       count(*)                                       AS total_gates,
       max(st.finished_at)                            AS last_touch
FROM songs so JOIN stages st ON st.song_id = so.id
GROUP BY so.id;

CREATE VIEW v_asset_pipeline AS
SELECT a.id AS asset_id, a.song_id, a.asset_key, a.name, a.cat, a.channel, a.status,
       count(i.id)                                      AS img_total,
       count(i.id) FILTER (WHERE i.picked = 1)          AS img_picked,
       count(i.id) FILTER (WHERE i.kind = 'final')      AS img_final,
       (SELECT count(*) FROM svgs v WHERE v.asset_id=a.id AND v.approved=1) AS svg_ok
FROM assets a LEFT JOIN images i ON i.asset_id = a.id
GROUP BY a.id;
```

## 13. 迁移

`PRAGMA user_version` 存 schema 版本，从 `1` 起。**当前 v2**（v1=10 张表；v2=新增 `docs` 表）。

`db.mjs init` 的 DDL 全是 `IF NOT EXISTS`，**可重复跑**，缺表会自动补上——加表不用写迁移脚本，跑一次 `init` 即可；只有加字段/改语义才需要迁移脚本。

- 加字段：`ALTER TABLE ... ADD COLUMN`，版本 +1，写进 `scripts/migrations/` 与本文档。
- 改字段语义：**新建表 + 搬数据 + 删旧表**，不原地改含义。
- 删表/删字段：先确认没有页面在读，再删，本文档同步删（不写"已废弃"）。
