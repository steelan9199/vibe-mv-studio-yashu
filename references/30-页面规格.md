# 页面规格（5 个页面）

> 原则：**每页只回答一个问题**。答不出来的内容不进这一页。
> P0 全部只读——没有输入框、没有表单、没有删除按钮。

## 0.0 数据来源：只从库读（老板 2026-10-23 定死）

**页面上的每一个字都必须来自一条 SQL。** 服务端渲染代码与前端 JS 里，渲染路径上不许出现目录遍历、不许 `readFileSync` 读 json/md。

| 允许 | 不允许 |
|---|---|
| `SELECT ... FROM songs/stages/docs/assets/images/svgs/skills/skill_runs/decisions/costs` | `fs.readdirSync(文件库)` 列图 |
| `SELECT path FROM images WHERE id=?` 再用它取字节 | 前端把路径传给后端取文件 |
| ingest 模块（写库时）扫盘 | 页面请求时扫盘 |

**唯一例外**：`/media/<id>` 返回图片/音频/视频的**字节流**——因为二进制进不了 SQL 行。流程固定为 `image_id → SELECT path → 拼 D:\vibe-mv-文件库\ → 读字节`。

**自检判据**：把 `D:\vibe-mv-文件库\` 改个名字，网页除图裂外，标题、状态、歌词、资产名、技能矩阵、成本数字**一个都不能少**。少了就是读错了地方。


## 0. 全局

| 项 | 规格 |
|---|---|
| 布局 | 顶部一条导航（首页 / 资产库 / 技能 / 成本），下方是内容区 |
| 宽度 | 内容区最大 1280px 居中；图墙允许更宽 |
| 字体 | 系统字体（`system-ui`），正文 14px，表格 13px |
| 颜色 | 沿用状态四色：`done` 绿 / `draft` 蓝 / `partial` 琥珀 / `todo` 灰 |
| 空状态 | 每个区块都必须有：一句人话 + 下一步该干什么（不许只写「暂无数据」） |
| 加载 | 首屏骨架屏，不转圈 |
| 刷新 | 顶部一个「刷新索引」按钮 → `POST /api/reindex` → 全页重载 |

## 1. 首页 `/`

**回答：我手上有几首歌、各自卡在哪、有几件事在等我。**

| 区块 | 内容 | 数据 |
|---|---|---|
| 顶栏统计 | 歌数 / 已出片数 / 待你决定 N 件 / 本月花费 | `v_song_progress` + `decisions` 未消费 + `costs` |
| 歌卡片列表 | 一行一首：标题、slug、七个小方块（每块一个关，按状态上色）、当前关一句话、最后动作时间 | `songs` + `stages` |
| 点卡片 | 进单歌页 | — |

卡片上**必须显示"当前关的一句话"**（`stages.note` 里最新一条），这是老板一眼恢复上下文的关键。没有 note 就显示"未填备注"。

空状态：`还没有歌。在对话框里说「建一首新歌，叫 XXX」，我来建。`

## 2. 单歌 `/song/<slug>`

**回答：这首歌每一关产出了什么。**

纵向时间线，从上到下 G0 → G5，每关一个区块。**已完成的收起，当前关展开**，可点击手动展开/收起。

每关区块的固定结构：

| 部分 | 内容 |
|---|---|
| 头 | 关卡代号 + 中文名 + 状态徽章 + 起止时间 |
| 备注 | `stages.note`（空白则显示"未填"） |
| 产物 | 按 `kind` 分派渲染（见下表） |
| 技能 | 这一关的 `skill_runs` 列表（技能名 + 耗时 + 是否成功） |

产物按 `artifacts.kind` 渲染：

| kind | 渲染成什么 |
|---|---|
| `audio` | `<audio controls>` + 时长 |
| `music` | 关键数字（BPM/时长/调性）从 `songs` 读；文件给下载链接 |
| `lyrics` | 逐字轴预览：显示前 3 句，点开看全部（等宽字体） |
| `storyboard` / `relay` | Markdown 渲染（服务端渲染成 HTML，不引前端库） |
| `story` | JSON 折叠树（默认收起） |
| `video` | `<video controls>` + 分辨率/时长/大小 |
| `export` | 只显示路径 + 一句"临时产物" |

**G3.5 特殊处理**：不按 artifacts 渲染，改成资产表——

```
资产名   分类   视角   通道   图(总数/已选/定稿)   SVG   状态
老乌龟   角色   背视   ai     5 / 1 / 0            —     draft
```

点资产行 → 展开图墙（缩略图网格），点图 → 大图 + `prompt / seed / workflow` 三件套。

空状态每关不同，例如 G2：`还没有逐字轴。在对话框里说「打开打轴页」，我帮你起。`

## 3. 资产库 `/assets`

**回答：跨所有歌，我一共有哪些资产、哪些图能用了。**

| 区块 | 内容 |
|---|---|
| 筛选条 | 歌（下拉）/ 分类（角色·道具·特效·背景）/ 通道（ai·svg）/ 状态 |
| 图墙 | 每张卡片 = 一个资产：主图（有定稿用定稿，否则用第一张 ref）、名字、分类标签、图数徽章 |
| 点卡片 | 抽屉：全部图（缩略图）、SVG 对照、提示词、成本小计 |

主图 priority：`images.kind='final'` → `picked=1` → 第一张 `ref` → 占位图。

**这一页是老板最常来的地方**，图必须能一屏看 20+ 张（缩略图 180px 见方）。

空状态：`还没有资产记录。资产清单出来之后，让 AI 存一次就有了。`

## 4. 技能 `/skills`

**回答：一首歌到底经过了哪些技能，各用了几次。**

| 区块 | 内容 | SQL |
|---|---|---|
| 调用矩阵 | 行=技能，列=歌，格=调用次数；按总数降序 | `group by skill, song` |
| 技能卡片 | 技能名、层级、一句话职责、版本、累计次数 | `skills` |
| 单歌工序时间线 | 选一首歌 → 按时间排开每次调用（技能名 + 关卡 + 时间 + 产物链接） | `skill_runs` |

矩阵的每一格**必须可点**，点开是这几次调用的明细（时间、耗时、成功与否、产出哪个文件）。点不开 = 只是装饰。

空状态：`技能表还没同步。点顶部「刷新索引」，我从技能目录里扫一遍。`

## 6. 接口清单

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/songs` | 歌列表 + 进度 + 当前关备注 |
| GET | `/api/song/:slug` | 单歌全量（songs/stages/artifacts/assets/images/svgs/runs/decisions/costs） |
| GET | `/api/assets?cat=&channel=&song=` | 资产 + 图统计 |
| GET | `/api/assets/:id` | 单资产的图、SVG、提示词 |
| GET | `/api/skills` | 技能表 + 调用矩阵 |
| GET | `/api/runs?song=<slug>` | 技能调用明细 |
| GET | `/api/costs` | 成本聚合 + 流水 |
| POST | `/api/reindex` | 重扫技能目录与文件库，补 sha256/尺寸（**唯一 POST**，属 ingest，不是页面渲染） |
| GET | `/media/<kind>/<id>` | 二进制字节流。**id 必须是库里的主键**：先 `SELECT path` 再取文件 |

### `/media` 的安全规矩（必须做）

- 只允许 `GET`；`<id>` 必须是整数主键，**不接受任何路径参数**（这一条从根上灭掉 `../../` 和任意文件读取）
- 查到 `path` 后 `path.resolve(文件库根, slug, path)`，仍须校验以文件库根开头，否则 403（防库里存了脏路径）
- `<kind>` ∈ `image` / `audio` / `video` / `svg`，与服务端查的表一一对应
